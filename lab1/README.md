## Вектор (`Vector3D`)

Вектор хранит координаты начала и конца (`Point3D`). Результат любой операции сохраняет **начало первого
операнда**, конец = начало + результирующее смещение.

- `getBegin()`, `getEnd()`, `getDirection()`, `length()`
- `+`, `+=`, `-`, `-=` - покоординатно по смещениям
- `*`, `*=` между векторами - **векторное** произведение; `*`, `*=` с числом (в т.ч. `число * вектор`)
- `/`, `/=` - деление на число (на ноль - `std::domain_error`)
- `cosineWith()` и оператор `^` - косинус угла (для нулевого вектора - `std::domain_error`)
- `<`, `<=`, `>`, `>=` - сравнение **по длине** (с точностью `kCoordinateEpsilon`), `==`, `!=` - по координатам обоих концов
- `<<`, `>>` - формат `[(x, y, z), (x, y, z)]`

> на GitHub - «деление на число» и «векторное произведение». Реализован вариант из `lab1.md`.

## Длинное целое (`BigInteger`)

Знак + модуль в системе счисления 10^9 (`std::vector<uint32_t>`, младшая цифра первая).

- конструкторы от `long long` и от строки, копирование/присваивание (правило нуля: вектор копируется сам)
- `+`, `-`, `*`, `/` и составные формы; деление усекает к нулю
- операции с обычным целым работают через неявный конструктор из `long long` (`a + 5`, `5 + a`, `a < 5`)
- `++`, `--` (префиксные и постфиксные), унарный `-`
- `==`, `!=`, `<`, `<=`, `>`, `>=`
- `explicit operator long long()` (при переполнении - `std::overflow_error`)
- `<<`, `>>`, `toString()`

## Вопросы для защиты (кратко)

- **Когда нужен конструктор копирования?** Когда класс владеет ресурсом (память, файл), и побитовое копирование
  привело бы к двойному освобождению/общему состоянию. У наших классов ресурсами управляет `std::vector`,
  поэтому достаточно сгенерированного компилятором (правило нуля).
- **Разница между `+` и `+=`?** `+=` меняет левый операнд и возвращает ссылку на себя (`*this`), `+` создаёт новый
  объект: берёт левый операнд по значению, вызывает `+=` и возвращает копию.
- **Зачем `const`?** В аргументах (`const T&`) - не копировать и не менять; после метода - метод не меняет объект;
  позволяет вызывать методы у константных объектов.
- **Почему `operator<<` не член класса?** Левый операнд - поток, а не наш объект.
- **Почему `explicit` у `operator long long`?** Иначе возможны неявные преобразования и неоднозначность перегрузок.
